## Tuning changes

### `src/config/ai.ts` — AI target speed

Baseline: AI pack (led by the cadet profile, target 34) convoyed at ~25–30 % behind a P1 player because the headway-braking follow model only caps cars catching slower rivals; the player won every race by a large, uncompetitive margin at every skill tier.

| Profile | targetSpeed before | targetSpeed after |
| --- | --- | --- |
| cadet | 34 | 42 |
| rider | 37 | 44 |
| veteran | 40 | 46 |
| ace | 43 | 48 |
| phantom | 46 | 50 |

Lane bias and reaction time unchanged. Lookahead/headway constants in `AIController.ts` were experimented on (LOOKAHEAD 12, RIVAL_LATERAL 4.5, STANDING_GAP 3, FOLLOW_GAIN 2.2) and reverted: they did not meaningfully change race outcomes and FOLLOW_GAIN 2.2 breaks the headway unit test in `tests/ai.test.ts`. Original constants kept.

### `src/config/career.ts` — event targets

Baseline: time attack targets (80/75/70 s) were ~3× longer than a clean 1-lap (24–26 s) — trivially passable; drift targets (400/500/650) were unattainable (measured full-lap drift max 338/364/538 for the career cars); race `targetTime` values (220–260 s) were ~3× longer than a real 3-lap (~70–112 s) and were not displayed for races (informational only).

| cup-1-e1 | race | city | targetTime 240 → 75 (informational; pass = P1) |
| cup-1-e2 | timeAttack | city | targetTime 80 → 30 |
| cup-1-e3 | drift | coast | targetScore 400 → 200 |
| cup-1-e4 | nitro | coast | targetScore 60 → 70, targetTime 90 → 40 |
| cup-1-e5 | race | city | targetTime 220 → 70 (informational) |
| cup-2-e1 | timeAttack | coast | targetTime 75 → 40 |
| cup-2-e2 | race | mountain | targetTime 260 → 110 (informational) |
| cup-2-e3 | drift | city | targetScore 500 → 220, targetTime 120 → 45 |
| cup-2-e4 | nitro | mountain | targetScore 70 → 75, targetTime 95 → 60 |
| cup-2-e5 | race | coast | targetTime 240 → 95 (informational) |
| cup-3-e1 | race | mountain | targetTime 250 → 110 (informational) |
| cup-3-e2 | timeAttack | city | targetTime 70 → 28 |
| cup-3-e3 | drift | coast → **mountain** | targetScore 650 → 320, targetTime 130 → 60 (track moved to the twistiest track for the finale) |
| cup-3-e4 | nitro | city | targetScore 75 → 80, targetTime 85 → 40 |

Rewards and unlock gates unchanged: 590/860/1220 currency per cup (~2650 total). Unlock order verified in simulation: swift (cup-1-e3) → vector (cup-1-e5) → tempest (cup-2-e3) → phantom (cup-2-e5) → apex (cup-3-e4).

Drift targets were set at ~55–60 % of the measured full-lap drift maximum (the best headless proxy for active drifting; a corner-only driver scores far less, 9–51, because the AI racing line keeps the car stable). This keeps every drift event comfortably passable for a player who drifts through most corners while making non-drifting fail.

## Not implemented (out of plan)

Genuinely absent from this branch (spec items the plan did not carry into implementation):

- **Spec §5.3 `aiLoadout` and difficulty modifiers:** `EventConfig` carries no per-event AI loadout or difficulty-modifier fields. Every race uses the fixed five-profile lineup (`cadet` → `phantom`) from `src/config/ai.ts` regardless of track, cup or event type.
- **Offline status / update UI:** `PwaService.getOfflineStatus()` and `PwaService.requestUpdate()` exist and are unit-tested (`tests/pwa.test.ts`), but no UI surface displays online/offline status or offers an update/reload affordance. The service worker is registered with `registerType: 'autoUpdate'` (`vite.config.ts`), so new versions activate in the background on the next navigation; a visible status indicator remains a future UX item.

Items the spec's HUD list called for (drift score, minimap) and the garage upgrade/cosmetic loop are implemented and covered by `tests/ui.test.ts` and `tests/game-integration.test.ts`.

## Residual hardware-specific notes

- Frame-time-dependent behavior (Auto quality adaptation thresholds, `WINDOW_FRAMES`/`SLOW_TARGET_FPS`/`FAST_TARGET_FPS`) is unit-tested in isolation but must be observed on a real device before a release claim.
- AI opponents cannot overtake the leader (the headway-braking follow model only caps catching cars; there is no overtake state machine). This is an architectural property, not a tuning knob; P1 holds P1 and the race challenge is crash avoidance / line quality / nitro. Acceptable for this scope.
- Drift targets assume a player who actively drifts corners; the headless drift proxy holds drift input continuously, so real player drift scores are expected to land somewhere between the corner-only proxy (9–51) and the full-lap proxy (338–681). Targets (200/220/320) were set with ~30–50 % margin below the full-lap proxy on the career cars.
